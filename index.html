FMCS Isaac Lab Update

This update upgrades the DDPM baselines in the Isaac Lab Franka experiments and adds a learned local field for OC-FMCS. It also brings the scripts up to date with current Isaac Lab releases. All earlier settings remain available through command-line flags.

Branch isaac-ddpm-fix Isaac Lab 2.3.2, Franka IK-Abs tasks Eval seed 2027 中文版

Overview

DDPM baseline

The baseline now uses a cosine noise schedule, predicts the clean action chunk and executes chunks in a receding horizon. Success rises from 0% to 62.5% on Reach and from 0% to 83.3% on Lift. The arm now moves smoothly, and the gripper switches about as often as the task requires.

Learned local field

The new method oc_fmcs_learned generates every action with a learned FMCS field conditioned on the active chart, while the chart atlas manages the handoffs. It reaches 45.8% on Reach and lifts the cube in 54.2–62.5% of Stack episodes.

Maintenance

Stack now has one phase per controller state, nine in total. The Lift script runs on current Isaac Lab releases, and a new flag supports environments with NumPy 2. The README commands match the script flags. The update also adds motion-smoothness metrics and an offline evaluation script.

Baseline

DDPM baseline upgrade

The upgraded baseline follows current practice for diffusion policies with few denoising steps. It changes three settings.

Cosine noise schedule

With 16 denoising steps the cosine schedule (squaredcos_cap_v2) brings the forward process to ᾱT ≈ 1×10−5. Training therefore covers the pure Gaussian noise that sampling starts from. The linear schedule used before, βt = linspace(1e-4, 0.02), was designed for 1,000 steps and ends at ᾱT = 0.851 after 16.

Clean-chunk prediction

The network now predicts the clean action chunk x₀. Demonstration chunks occupy a small part of the 112- to 128-dimensional action space, so the width-256 MLP learns them well within the training budget. We measured the effect offline, on expert states from the evaluation seed. With the cosine schedule, x₀ prediction lowers the first-action error from 21.2 cm to 3.2 cm, close to direct regression at 2.3 cm. Endpoint prediction gives the same gain for flow matching. Li and He (2025) report a similar result for image generation in Back to Basics: Let Denoising Generative Models Denoise.

Receding-horizon execution

The policy executes 8 actions of each 16-step chunk and then samples a new chunk, as in Diffusion Policy. It also samples a new chunk as soon as the phase changes. The sampler clips x₀ to the demonstration range, uses the posterior variance β̃ and runs on EMA weights with decay 0.995. The resulting commands are smooth and consistent. On Stack the upgraded DDPM moves as smoothly as the chunk MLP and the phase controller. Its gripper switches 2.5 times per episode, close to the two switches that one grasp and one release need.

OC-FMCS

OC-FMCS execution and the learned local field

In the robot experiments oc_fmcs executes the chart atlas with a phase controller (ScenarioController, or PhaseFeedbackController for Lift). For each chart the controller sets an end-effector target and a gripper command. It hands off to the next chart once the end effector is within 0.12 m of the target and has stayed for a minimum time. Inside a chart the local field ct(z − x) points toward the target, and Isaac Lab's differential IK executes it. The Stack task uses nine charts.

The learned baselines (BC, chunk MLP, DDPM and their phase-conditioned versions) are trained on demonstrations recorded with this controller.

Learned local field

The new method oc_fmcs_learned learns the local field inside each chart. The atlas still selects the active chart k and decides the handoffs, and the learned field produces every action.

  • The field acts on 16-step action chunks, conditioned on the observation and a one-hot code for chart k.
  • The feasible set of each chart is the bounding box of its demonstration chunks in normalized space, enlarged by 0.1 in each dimension. The prior is a standard Gaussian projected onto this box, as in FMCS.
  • The network predicts the endpoint ẑ, and the velocity is v = (ẑ − x) / (1 − t), which is the FMCS conditional field ct(z − x). The endpoint is clipped to the box, so every Euler step stays inside the chart. Sampling uses 10 Euler steps.

The learned field carries out approach, grasp and lift on its own. With 24 demonstrations it lifts the cube more than three times as often as the upgraded DDPM. Stacking also depends on the handoff out of the lift chart, which currently uses the waypoint test of the phase controller. A handoff based on object state, such as the height of the cube and its distance to the target, is a natural next step for this method.

Reproduction

Run the script from the repository root. main produces the main results and ablation runs each setting change on its own. Each run is a separate Isaac process and needs about 2 GB of GPU memory.

export ISAACLAB_PYTHON=<isaac-lab-python>
bash docs/isaac_ddpm_fix/run_isaac_ddpm_fix.sh main
bash docs/isaac_ddpm_fix/run_isaac_ddpm_fix.sh ablation

A single Stack run:

"$ISAACLAB_PYTHON" experiments/isaaclab_multitask_policy_baselines.py \
  --scenario stack --num-envs 24 --steps 240 --hidden-dim 256 \
  --diffusion-train-steps 1800 --fm-train-steps 1800 \
  --stack-overlap-threshold 0.12 --stack-lift-z 0.26 --stack-place-z 0.095 \
  --stack-close-dwell 1.2 --stack-place-dwell 1.2 --stack-release-dwell 1.6 \
  --eval-methods diffusion_policy,phase_diffusion_policy,oc_fmcs,oc_fmcs_learned \
  --device cuda:0 --headless --out results/my_run/metrics.json

Offline evaluation. Export demonstrations first, then run the script in any Python environment with PyTorch.

"$ISAACLAB_PYTHON" experiments/isaaclab_multitask_policy_baselines.py \
  --scenario reach --steps 120 --num-envs 24 --demo-episodes 8 \
  --dump-demos dumps/reach_e8.pt --device cuda:0 --headless
python experiments/offline_policy_diag.py dumps/reach_e8.pt --episodes 1 8

In environments that combine NumPy 2 with a pinocchio build for NumPy 1.x, add --stub-dex-retargeting, or set EXTRA=--stub-dex-retargeting for the rerun script. The flag replaces teleoperation modules that evaluation does not use.

Result folders are in docs/isaac_ddpm_fix/results/. The *_fixed folders hold the upgraded runs and the *_legacy folders the earlier configuration. The other folders change one setting at a time.
