# Isaac Lab experiments: oc_fmcs and the upgraded DDPM baseline

The full write-up is a single page: [`index.html`](index.html) (English) and
[`index.zh.html`](index.zh.html) (Chinese), published at
<https://continuumcoder.github.io/Flow-Matching-in-Convex-Invariant-Set/>.
This file lists the main points and the files.

## Summary

1. **The 3D `oc_fmcs` is a scripted controller.** In
   `isaaclab_multitask_policy_baselines.py` the branch is
   `action = controller.action(obs)`: a `ScenarioController` finite-state machine
   driving differential IK, with no learned velocity field. Every learned baseline
   imitates demonstrations generated by this controller. The new method
   `oc_fmcs_learned` lets a learned, chart-conditioned FMCS field produce every
   action: 45.8% on Reach and 4.2–8.3% stacking on Stack, held back mainly by the
   handoff gate of the lift state.
2. **Upgraded DDPM baseline.** The original configuration (16 steps of the linear
   1e-4..0.02 schedule, so ᾱ_T = 0.851 while sampling starts from pure noise;
   ε-prediction with a width-256 MLP; resampling at every control step) gives 0%.
   With a cosine schedule, x₀-prediction, x₀ clipping, EMA and 8-of-16-step
   execution:

   | Task | Demos | DDPM original → upgraded | Scripted oc_fmcs |
   |---|---:|---:|---:|
   | Reach | 24 | 0% → 62.5% | 100% |
   | Lift | 192 | 0% → 83.3% | 97.9% |
   | Stack, stacked | 24 | 0% → 4.2–8.3% | 70.8–79.2% |
   | Stack, stacked | 192 | — → 41.7–50.0% | 62.5–66.7% |

3. Other updates: Stack uses 9 phases to match its 9 controller states; Lift demo
   collection runs in inference mode for recent Isaac Lab; the Stack command in the
   READMEs uses `--scenario` and `--out`.

## Files

- `index.html`, `index.zh.html`: the write-up (questions, evidence, results,
  implications for the paper, reproduction).
- `run_isaac_ddpm_fix.sh`: rerun script; `main` for the main results, `ablation`
  for the ablation.
- `results/<run>/metrics.json`: full metrics of every run; `results/offline_diag/`:
  offline diagnosis.

| Folder | Configuration |
|---|---|
| `reach_legacy`, `stack_24demos_legacy` | Original (linear schedule, ε, no clipping, no EMA, per-step resampling) |
| `lift_legacy_schedule` | Lift with the linear schedule and per-step resampling (keeps x₀-prediction) |
| `stack_24demos_cosine_only` | Cosine schedule only |
| `reach_cosine_eps`, `stack_24demos_cosine_eps` | Cosine, clipping, EMA, 8-step execution, still ε |
| `stack_24demos_cosine_eps_6000steps` | Same, 6,000 training steps |
| `reach_fixed`, `stack_24demos_fixed`, `stack_192demos_fixed`, `lift_fixed` | Upgraded (current defaults) |
| `stack_*_fixed_noclamp` | DDPM upgraded; oc_fmcs_learned without endpoint clipping |

In the ablation folders `oc_fmcs_learned` is an earlier velocity-predicting
version; use the `*_fixed` folders for it.
